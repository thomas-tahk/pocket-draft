Battle Build Plan

The final battle spec cut into 4 milestones, each ending in a game you can play and judge. Nothing is created on GitHub until you approve this list. Row ids (S4, T9…) point into the battle spec; each GitHub issue will quote its rows in full.

Three things to OK with the list

  1. Screen issues can't be checked by a Go test. Everything the screen decides (what glows, prompts, banners, modifier breakdowns) comes from the Go engine and gets a Go test. Drag, drop and layout get a browser test on a phone-sized screen. That needs Playwright as a new dev-only dependency. Without it, screen issues have no automatic done check and I'd have to check them by hand at milestone end.
  2. Draft pool during milestones 1–3. Until milestone 4 finishes card text, the draft only offers cards whose text already works, so every test game plays correctly. Milestone 4 ends with every card in the pool.
  3. How it runs. Each milestone gets its own branch. Agents take the next unblocked issue, write the failing test, make it pass, and merge into the milestone branch when all tests pass. Questions go to docs/questions/M#.md and the agent moves on. pd.wasm is rebuilt once per milestone, not per issue, because agents would otherwise collide on that one binary file. At milestone end I stop and hand you a summary, the questions, and play steps. Merging the milestone into main, and deploying, stay your call.
